# Agent, skill, and MCP setup

Installed for this repository on 2026-10-16. These files travel with the project;
the user's global Codex model/settings were not replaced.

## Agents

All eleven requested VoltAgent profiles are installed in `.opencode/agents/`.
The supplied conversion script is saved as `scripts/install-subagents.sh`.
It strips Claude `tools`/`model`, adds `mode: subagent`, and denies edit/bash for
the two reviewers. It validates missing inputs first and uses `ENVIRON` for the
permission block because macOS BSD awk rejects the original multiline `-v`.

Codex does not load OpenCode agent files. The matching eleven standalone TOML
profiles are in `.codex/agents/`, generated by `scripts/convert-codex-agents.py`.
They select `gpt-6-luna` with high reasoning. `.codex/config.toml` enables agents
and caps concurrent child threads at three. Root `AGENTS.md` requires actual
delegation, scoped file ownership, and review after each implementation batch.

The read-only OpenCode permissions are enforced by OpenCode. Codex supports
disabling the shell capability, which is set for both reviewers, but reviewers
still inherit the parent permission boundary. Their no-edit rule is an instruction,
not a separate sandbox. See [official subagent documentation](https://learn.chatgpt.com/docs/agent-configuration/subagents).

If a desktop runtime cannot select a named custom profile, the root instructions
describe a supported fallback: load the profile into a normal spawned subagent's
task. Do not claim the profiles have been executed merely because they parse.

`.agents/skills/impeccable/`, including its references and launcher. This is
distinct from the pre-existing global `impeccable-design` skill.
The install used the official skill-installer helper with a pinned upstream commit.
Sources and licenses are in `docs/vendor/`. The installed skill was subsequently
visible in the session skill catalog. New configuration may require reopening or
restarting the project chat on another machine.

The launcher was exercised with its engine v0.1.15 in a temporary cache:

```sh
IMPECCABLE_HOME=/tmp/spill-impeccable-runtime DO_NOT_TRACK=1 \
  sh .agents/skills/impeccable/scripts/impeccable context --target apps/mobile
```

It completed. No automatic UI hooks were installed. On a future machine the
launcher downloads the pinned engine on first use; the temporary cache is not
part of the repository. For native React Native reviews use native guidance;
an empty web detector result is not evidence of native design quality.

## MCP servers

Codex reads `.codex/config.toml`; `.mcp.json` is the existing configuration for
other compatible clients. Both now include gcloud. Do not assume `.mcp.json`
alone configures Codex. [Official MCP configuration](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

| Server | Configuration | Remaining connection requirement |
|---|---|---|
| Supabase | Enabled; exact requested project `fcefeiwvnzdfazwxdejy` and feature list; authenticated table discovery succeeded during review | Reauthenticate with `codex mcp login supabase` if a later session lacks access; migration revision/policy behavior remains unverified |
| gcloud | Enabled; `npx -y @google-cloud/gcloud-mcp` | Existing gcloud CLI credentials and correct project; package startup is verified |
| Bright Data | Registered but disabled in Codex; placeholder is not a credential | Real API token and activation; no scraping was run |

For Supabase, the OAuth prompt requests the scopes used by the selected features.
The configured project is the one supplied by the owner; do not infer whether it
is staging or production from the name. Verify the environment before database work.

Bright Data offers both `/sse` and `/mcp`; Codex's native URL transport expects
Streamable HTTP, so the prepared entry uses `/mcp` with the same groups.
[Bright Data transport documentation](https://docs.brightdata.com/products/mcp-server/remote/quickstart).
Do not put the real query-string token into tracked `.codex/config.toml`.
For a CLI session, supply an environment token and override only that session:

```sh
# Set BRIGHTDATA_MCP_TOKEN privately in your shell first; never paste it into a prompt.
codex \
  -c "mcp_servers.brightdata.url=\"https://mcp.brightdata.com/mcp?token=${BRIGHTDATA_MCP_TOKEN}&groups=advanced_scraping,social\"" \
  -c 'mcp_servers.brightdata.enabled=true'
```

For persistent desktop use, configure the token through local MCP settings or
a local stdio wrapper with environment-backed credentials. The prepared remote
entry deliberately remains disabled until that credential is supplied. The
existing `.mcp.json` retains its environment placeholder and SSE URL; its client
must support both interpolation and that transport.

gcloud prerequisites are Node 20+ and the installed/authenticated gcloud CLI.
[Official package instructions](https://github.com/googleapis/gcloud-mcp).
`codex mcp list` confirms configuration discovery; it does not prove a successful
server handshake or grant access to a cloud project.

Validation recorded through 2026-10-18: all eleven TOML profiles were generated
and parsed; GPT-6 Luna delegation ran for tooling review and a bounded FastAPI
source review. The latter confirmed queue/import/search issues used in the plan.
This proves delegation works in this runtime, not that every client automatically
loads every named profile. The tooling reviewer had no permitted local read tool;
its feedback was limited to supplied configuration facts. Do not count it as an
independent filesystem audit.

Supabase table discovery reported RLS enabled on the listed public application
tables. It did not verify effective policies or the API connection role. Automatic
approval review hit a usage limit before a migration-version query and gcloud
project lookup executed. gcloud package startup was checked, but project access
was not established by that check. Bright Data has not connected or scraped;
its real token is still required. No live data was mutated by setup.

## Reproduce agent installation

Use the commits in `docs/vendor/tooling-sources.json` when checking out sources:

```sh
bash scripts/install-subagents.sh /path/to/awesome-claude-code-subagents "$PWD"
python3 scripts/convert-codex-agents.py
codex mcp list
```

No model handoff chat was created. Select GPT-6 Luna in the next execution chat
and paste `docs/LUNA_START_PROMPT.md`.
